## 現在の状態

メッセージの投入・取り出しが動く最小実装、使用例のテスト、最初の課題とレッスンを用意した段階。学習者の回答はまだ確認しておらず、学習課題は未完了。作業管理には GitHub Issues を使う。

## 動かす

Rust 2024 Edition に対応する Rust と Cargo を使う。外部クレートへの依存はなく、リポジトリのルートで次を実行できる。

```sh
cargo test --offline
```

これはライブラリなので、`cargo run` ではなくテストから動作を確かめる。使用例だけを実行するときは `cargo test --offline --test broker` を使う。

## 出発点の仕様

- `Broker::new()`：空のブローカーを作る。
- `publish(String)`：本文の所有権を受け取り、キューの末尾に入れる。
- `receive() -> Option<String>`：先に投入した本文から一件ずつ取り出す。空なら `None` を返す。

受信済みの本文はキューに残らない。空になった後も再び投入して受信できる。メッセージの ID、宛先、処理完了の管理はまだ持たない。

最初に [tests/broker.rs](tests/broker.rs) を読み、次に [src/lib.rs](src/lib.rs) の所有権の移動を追う。

## 学習の順序

既存製品を再現するのではなく、学習用の独自仕様で進める。

1. 単一キュー：投入したメッセージを順に取り出す。所有権の移動と、参照を返す場合の違いを学ぶ。
2. 処理中の管理：受信と処理完了を分ける。ACK で完了、NACK でキューに戻す仕組みを通して、状態とデータの持ち方を考える。
3. 複数キュー：宛先キーに応じて一つのキューを選ぶ。エラー処理とコレクション操作を整理する。
4. 抽象化：本文をジェネリクスで扱う。宛先の完全一致・接頭辞一致という二つの選択方針を具体的に実装してから、共通部分を trait にする。

各段階の細かな仕様は、取りかかる前に課題文で確定する。次の段階は、前の段階で動いていたコードへの仕様変更として進める。

## 最初の取りかかり方

メッセージの投入と一件の取り出しが動く最小実装と、使用例になるテストを用意している。未実装の穴を埋める雛形ではなく、小さくても動く Rust ライブラリを出発点にする。

1. テストを動かし、投入した順に取り出せることを確かめる。
2. 一つのメッセージが呼び出し元からキュー、受信側へ移る箇所を読む。
3. [最初の課題](exercises/01-peek.md)を読み、「取り出さずに、先頭のメッセージを参照する操作」を追加する。
4. 空の場合の扱いと、参照したメッセージがキューに残ることを確かめる。

最初の課題の解答や、ACK・振り分けなどの後続機能は、出発点の実装に含めない。

## 各課題の進め方

1. 仕様と完了条件を読む。
2. 既存コードを読み、自分で変更する。
3. テストで挙動を確かめ、自分の判断を説明する。
4. 同じ仕様を満たす参考実装を読み、違いを比較する。
5. 比較で得た理由に基づいて必要な改善を行い、完了した段階をコミットで残す。

参考実装は唯一の正解ではない。動作が合うだけでなく、[到達の目安](MISSION.md#到達の目安)に沿って判断を説明できることを大切にする。
