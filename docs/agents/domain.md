# ドメイン文書

## 調査前に読むもの

- リポジトリ直下の `GLOSSARY.md`：対象の用語と定義。
- `docs/adr/`：対象に関係する設計判断の記録。

存在しない文書は読み飛ばして作業を続ける。不在を問題として報告せず、空の用語集や ADR を先回りして作らない。用語や判断が実際に固まった時点で記録する。

## 配置

このリポジトリは単一コンテキストとする。用語集は `GLOSSARY.md` 一つに集約し、ADR は `docs/adr/` に置く。コンテキスト別の分割や `GLOSSARY-MAP.md` は設けない。

## 用語をそろえる

Issue、設計案、調査の仮説、テスト名でドメインの概念を扱うときは、`GLOSSARY.md` の定義を使う。避けると定めた同義語へ置き換えない。

必要な概念が載っていなければ、既存の用語で表せないか確認する。本当に不足している場合は、`domain-modeling` で整理する対象として記録する。

## 設計判断との整合

既存の ADR と矛盾する提案は、該当する ADR と再検討する理由を明示する。以前の判断を黙って上書きしない。
