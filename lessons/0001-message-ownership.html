LESSON 01 / 読む・予想する・説明する

この本文は、今だれのもの？

今日のゴールは、投入前・投入後・受信後で、本文の所有者を説明すること。まだ peek は実装しない。

読むための最小限の知識

String を値として関数へ渡すと、所有権が移る。戻り値でも所有権を移せる。一方、参照を渡す場合は、所有者を残したままアクセスする。

原典：Rust Book：関数と所有権、参照と借用。

1. 一件の本文を追う

使用例のテストから、一件の流れだけを抜き出した。必要に応じて 実装を見ながら、A・B・C の直後の所有者を考えよう。

let mut broker = Broker::new();
let first = String::from("注文を受け付けた"); // A
broker.publish(first);                     // B
let received = broker.receive()
    .expect("最初のメッセージがある");       // C

expect は値があれば中身を取り出す。ここでは先に一件投入しているので、その本文を受け取れる。公式仕様

2. コンパイル前に予想する

  1. A・B・C それぞれの直後、本文を所有しているのはどこ？
  2. B と C の間に println!("{first}"); を入れたら、コンパイルできる？ 理由は？
  3. publish の後も broker を使えるのはなぜ？ first と扱いが違う箇所を型から探そう。

まず自分の言葉で、この会話に回答してね。分からない箇所は「ここが分からない」で大丈夫。回答を見て、必要なところだけ一緒に確かめる。

自分で答えたあとに、考え方を確認する

A では first が所有する。B の呼び出しが終わると、本文は broker 内のキューに移っている。C ではキューから取り出した本文を received が所有する。

B の後に first を使うとコンパイルできない。publish の引数 message: String へ値を渡しているから。一方、ブローカーは &mut self として借りており、呼び出し元が所有したままなので、呼び出し後も使える。

receive が返した Option<String> から expect で本文を取り出し、received に移している。「元の変数名に戻る」わけではない。

3. 読み直す前に、思い出す

次回の開始時にこのページを閉じたまま、publish と receive の間で本文がどこにあるかを説明してみよう。

今日の説明ができたら、最初の実装課題へ進む。所有権を渡す受信と、所有権を残す読み取りの違いを考える。

復習は 所有権を読むためのメモへ。原典を読むなら、まず Rust Book の「Ownership and Functions」と、その次の「Return Values and Scope」だけで十分。
